Both branches produced a valid 10-node workflow with three LangChain agents and a shared chat model: 0 invalid nodes, 0 orphans, all six required capabilities covered. Correctness is a genuine tie — the gap is entirely in what the workflow cost to produce.

What each axis measures

Correctness — 35 %

Does it work, and does it do what was asked. Three deterministic components, audited against the live instance:

ComponentShareSource
Requirement coverage40 %Six capabilities checked on node types and wiring — never on node names
Node schema validity40 %n8n server RPC validate_node_config, per node
Graph integrity20 %Adjacency traversal, orphan detection, AI sub-connections

Coverage exists because the other two are normalised by the workflow's own node count, which made doing less free: an earlier run scored a 4-node workflow with no triage step 100/100 against a 15-node one that fulfilled the brief.

Token efficiency — 35 % · Build time — 30 %

Both are Universal Minimax ratios: the better branch scores 100, the other degrades proportionally — Score(X) = 100 × min(A,B) / X. No arbitrary thresholds, no floor effect.

Setup — measured, not scored

Installation is paid once and amortises away; build time and tokens are paid on every workflow. Keeping setup in the score let a one-off cost decide the ranking — at 10 % it moved 6.07 points on a gap of 5.54. It is still reported:

Acquisition is excluded on both sides: each carries a benchmark artefact. n8n-as-code installs from local tarballs because the build under test is unpublished; Native MCP has its worker hand-roll an HTTP client because the runtime ships no wired MCP client. A real user of either does neither.

How contamination is prevented

Sequenced, not parallel

Branch A builds alone, is audited, and its workflow is deleted from the instance before branch B is dispatched. Copying is impossible, not merely forbidden.

Opaque names

Each branch gets an unguessable token (bench-3f9a1c72), never a shared predictable format that would let the two workflows recognise each other.

Fixed, archived prompt

The builder prompt is the confinement block plus the verbatim brief. The orchestrator adds nothing, and the exact text is written to disk before dispatch.

No rubric in the sandbox

Scoring documents stay out of the workers' reach. An agent that can read how it is graded optimises for the grader.

These rules are not precautionary boilerplate — each replaces a defect found in an earlier run, including an orchestrator-improvised prompt clause that silently deleted the AI-agent capability from both branches at once.

Against n8n-as-code

  • node-info --compact omits per-parameter option values, so it is not sufficient to author a node alone — the third run to report it.
  • push rewrote the local file and dropped the per-node notes fields set in the decorators. Silent data loss on a round-trip.
  • workspace status --json exposes accessStatus: "unknown" without the pointer to env status that the text output already carries.

Against Native MCP

  • The server auto-assigned an existing user credential to the agent nodes during create_workflow_from_code, although the builder never requested one.
  • validate_node_config reports Required field subnodes is missing for Agent nodes whose sub-connections are correctly wired.
  • search_nodes takes queries (array), not query; get_workflow_best_practices requires an argument not discoverable from the tool name.

Honest limits

  • One run per branch. The 1.30× build and token gaps are single observations, not separated from run-to-run variance.
  • Correctness did not discriminate. Both branches scored 100, so 35 % of the composite is constant here and the ranking is decided by the cost axes alone.
  • Ambition is not measured. Correctness asks whether a workflow works and covers the brief. Whether it is elegant or inventive is a separate judgement, not yet implemented.
  • Not numerically comparable to earlier runs: the worker runtime and model changed.
